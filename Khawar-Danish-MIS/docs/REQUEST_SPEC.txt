## 1. Project context and priorities

This system is for a local educational center in Afghanistan. Its users have limited computer skills.

The center provides:
- Kankor university entrance preparation.
- Foreign language courses, including English, Chinese, and German.
- Literacy classes.
- Calligraphy.
- Core school subjects.
- Other courses that administrators can define later.

Different teachers teach different subjects, batches, and schedules.

Prioritize:
1. Correct and reliable daily operations.
2. Ease of use for nontechnical staff.
3. Fully offline operation.
4. Low hardware and software requirements.
5. Accurate financial records.
6. Beautiful, consistent, professional design.
7. Maintainable code and straightforward installation.

Use “Khawar-Danish Educational Center” as an editable default name. Make the center’s name, logo, address, phone numbers, and document footer configurable.

## 2. Technology and offline operation

Use:
- PHP with a simple, well-organized MVC-style architecture.
- MySQL or MariaDB.
- HTML5 and CSS3.
- Bootstrap 5 with local RTL and LTR assets.
- Vanilla JavaScript unless a small local library is clearly necessary.
- PDO with prepared statements.

Target a modest Windows computer running WAMP or XAMPP, approximately 4 GB RAM and an ordinary dual-core processor.

Prefer plain PHP over a heavyweight framework for this project. Do not require Node.js, Docker, Redis, cloud services, or a development build server for installation or daily use.

All fonts, icons, stylesheets, scripts, and dependencies must be bundled locally. Do not use CDNs, remote fonts, external APIs, telemetry, or online authentication.

The installed system must function without any internet connection, including printing, reports, authentication, and backup. Explain honestly that the initial acquisition of WAMP/XAMPP or other prerequisites may require a separate download.

Support localhost operation and optional use across a trusted local network. Structure the application so future online deployment is possible without requiring cloud infrastructure now.

## 3. Language and localization

The default interface must be Dari/Persian with proper RTL layout. Provide English as a secondary language with LTR layout.

Use centralized translation dictionaries. Translate navigation, forms, validation errors, notifications, reports, and printable documents. Do not scatter untranslated text throughout the code.

Use a readable, locally bundled font that supports Persian/Dari characters and include its license.

Requirements:
- UTF-8 throughout and utf8mb4 in the database.
- Correct rendering of mixed Persian text, English text, phone numbers, and student identifiers.
- Afghanistan timezone: Asia/Kabul.
- Default currency: AFN.
- Gregorian date storage with Solar Hijri/Shamsi display and input support.
- Validated date conversion with a clearly labeled calendar mode.
- Monthly attendance sheets must use the actual number of days in the selected calendar month.
- Accept Persian and Latin digits in relevant numeric inputs and normalize them safely.

## 4. Users, permissions, and security

Provide one initial administrator account with full access. The administrator must be able to create, edit, deactivate, and manage additional users.

Provide configurable roles and permissions, with sensible defaults such as:
- Administrator.
- Registrar.
- Accountant.
- Teacher or attendance operator.
- Read-only user.

Permissions must control actions such as viewing, creating, updating, deleting, printing, exporting, managing finances, and accessing settings.

Enforce permissions on the server for every protected route and action, not only by hiding interface buttons. Limit teacher access to assigned classes where applicable.

Implement:
- Secure password hashing using PHP password_hash and password_verify.
- Secure session handling and session regeneration after login.
- Configurable inactivity timeout with a warning where practical.
- CSRF protection.
- Output escaping and input validation.
- Login attempt throttling.
- Safe file-upload validation.
- Protection against direct access to configuration, backups, and private uploaded files.
- Prevention of deactivating or deleting the last active administrator.

Provide offline password recovery through administrator-assisted reset. For the sole administrator, provide a documented local recovery procedure that requires access to the server computer. Do not use an email-dependent reset flow or a permanent backdoor password.

- Cash/bank movement reports.
- A clearly labeled cash-basis surplus/deficit report.

Include understandable examples in the user guide explaining balances, discounts, refunds, and payroll percentages.
